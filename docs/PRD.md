# PRD — BASAK WITCH 부스 QR 주문 관리 시스템

## 1. 개요
학교 축제 **연광제 2026** 7번 부스 **BASAK WITCH**(튀김산도·음료)에서 쓰는 QR 주문 관리 시스템이다.
손님은 부스 앞 QR 코드를 찍어 폰으로 메뉴를 고르고 송금하며, 부스 안에서는 노트북의 주방 화면으로 주문을 처리한다.

## 2. 배경과 문제
- 부스를 운영하면서 주문을 종이에 손으로 받아 적고, 입금 여부와 조리 순서를 사람이 하나하나 확인하고 대응해야 했다.
- 손님이 몰리는 시간에는 주문이 빠지거나 순서가 꼬이기 쉽다.
- 어떤 메뉴가 품절됐는지, 남은 개수가 몇 개인지 실시간으로 파악하기 어려워 다 팔린 메뉴를 주문받을 수 있다.
- 손님은 자기 음식이 언제 나오는지 몰라 부스 앞에 계속 서 있어야 한다.
- 주방은 지금 무엇을 몇 개 만들어야 하는지 한눈에 보기 어렵다.

## 3. 목표
1. 손님이 앱 설치나 회원가입 없이 폰 브라우저만으로 주문·송금을 마친다.
2. 주방은 화면 하나로 입금 확인 → 조리 → 수령까지 주문을 처리한다.
3. 손님은 주문 상태와 대기 순서를 실시간으로 보고, 준비되면 알림을 받는다.
4. 운영 중에도 가격·품절·남은 수량·세트 할인을 화면에서 바로 바꾼다.

## 4. 사용자
| 사용자 | 기기 | 하는 일 |
| --- | --- | --- |
| 손님 | 자기 폰(브라우저) | QR 접속 → 메뉴 선택 → 주문 → 송금 → 대기·수령 |
| 부스 운영자(주방) | 노트북 | 관리자 로그인 → 입금 확인 → 조리 → 수령 처리, 메뉴·재고 관리, 매출 확인 |

## 5. 사용 흐름
1. 손님이 QR을 찍어 고객 화면을 연다.
2. 바삭 세트(튀김산도 + 음료) 또는 단품을 담고, 입금자 이름과 연락처를 입력해 주문한다.
3. 주문번호와 금액이 나오고, 토스·카카오페이로 바로 보내거나 계좌번호를 복사해 송금한다.
4. 주방에서 입금을 확인하면 주문이 `조리 중`이 되고, 손님 화면의 대기 현황이 바로 바뀐다.
5. 조리가 끝나 주방에서 `수령 가능`을 누르면 손님 폰에 소리·진동·팝업 알림이 뜬다.
6. 손님이 주문번호를 보여 주고 받아 가면 주방에서 `수령 완료`로 처리한다.

| 우선순위 | 화면 | 기능 | 설명 |

| P0 | 고객 | 세트·옵션 선택 | 세트는 튀김산도 맛과 음료를 고르고 할인 적용, 청귤에이드는 청귤차로 변경 가능 |
| P0 | 고객 | 주문 | 수량 조절, 입금자 이름·연락처 입력, 주문번호 발급 |
| P0 | 고객 | 송금 | 주문 금액이 들어간 토스 송금 링크, 카카오페이, 계좌번호 복사 |
| P0 | 고객 | 실시간 대기 현황 | 내 주문 상태, 내 앞 대기 팀 수, 전체 대기열(주문번호만 공개) |

| P0 | 관리자 | 지금 만들 메뉴 | 조리 중 주문의 메뉴별 합계(세트 구성품 포함) |
| P0 | 공통 | 서버 계산 | 가격·세트 할인·재고 차감은 DB 함수에서 다시 계산 |
| P1 | 고객 | 수령 알림 | `수령 가능`이 되면 소리·진동·팝업·탭 제목 깜빡임 |

| P1 | 관리자 | 매출 | 1일차·2일차·전체 매출(입금 확인된 주문 기준) |
| P1 | 관리자 | 조리 중 항목 체크 | 주문 안의 메뉴를 하나씩 눌러 완료 표시 |
| P2 | 관리자 | 수동 주문 | 고객 화면을 쓸 수 없을 때 주방에서 직접 주문 입력 |
| P2 | 공통 | 데모 모드 | `?demo` 주소로 실제 DB 없이 고객·주방 화면을 모두 체험 |

## 7. 화면 구성
- **고객 화면** (`index.html`): 메뉴 → 주문 확인 → 송금 → 대기 현황의 4단계.
- **관리자 화면** (`admin/`): 로그인, 지금 만들어야 할 메뉴, 주문별 작업(상태 필터), 매출, 메뉴 가격·판매·품절 설정, 수동 주문.

## 8. 데이터와 기술
- 정적 HTML/CSS/JS(빌드 없음) + **Supabase**(PostgreSQL, Auth, Realtime) + **GitHub Pages** 배포.
- 테이블: `booth_settings`, `booth_menu_items`, `booth_orders`, `booth_order_items`, `booth_public_queue`, `booth_admins`.
- DB 함수(RPC): `booth_create_order`, `booth_get_order`, `booth_admin_create_order`, `booth_is_admin`.
- DB 구조는 `supabase/migrations/`의 SQL로 관리하고 Supabase CLI로 적용한다.

## 9. 비기능 요구사항
- **보안**: 브라우저에는 publishable key만 둔다. RLS로 손님은 메뉴와 공개 대기열만 읽고, 입금자명·연락처는 관리자만 본다. 주문은 DB 함수로만 만든다.
- **모바일**: 320~430px 폰 폭에서 메뉴 이름·설명이 어색하게 줄바꿈되거나 버튼과 겹치지 않는다.
- **실시간**: 주방에서 상태를 바꾸면 손님 화면이 새로고침 없이 바뀐다.
- **배포**: DB 마이그레이션을 먼저 적용한 뒤 화면을 배포한다. 바뀐 JS/CSS는 `?v=` 버전을 올려 폰 브라우저 캐시를 피한다.
