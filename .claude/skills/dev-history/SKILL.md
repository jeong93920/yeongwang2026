# dev-history — 대화 기록과 커밋으로 개발 과정 복원하기

기억으로 쓰지 않는다. 모든 문장은 대화 기록 한 줄 또는 커밋 하나로 뒷받침되어야 한다.

## 1. 기록 찾기
1. 대화 기록 폴더는 `~/.claude/projects/<작업 폴더 경로의 영문·숫자 외 문자를 '-'로 바꾼 이름>/`이다.
2. 폴더나 저장소 이름을 바꾼 적이 있으면 **옛 이름의 폴더도** 찾는다. (이 프로젝트는 `여울제/yeoul2026` → `연광제/yeongwang2026`)
3. 30일이 지난 기록은 지워질 수 있으니, 기록이 없는 기간은 커밋 메시지만으로 쓰고 그렇다고 밝힌다.

## 2. 기록 줄이기
`.jsonl` 원본은 수십 MB라 그대로 읽지 않는다. 함께 들어 있는 스크립트로 시간순 텍스트로 줄인다.

```bash
python3 -I .claude/skills/dev-history/scripts/condense.py <원본.jsonl> <출력.txt>
```

출력 한 줄은 `[MM-DD HH:MM] USER|CLAUDE|TOOL|RESULT: 내용` 형식이다(한국 시간). 사용자 요청, Claude의 답, 도구 호출(작업 목록·질문과 답·git 커밋 포함)만 남는다.

## 3. 사건 뽑기
줄인 기록을 구간별로 읽으며 사건을 하나씩 적는다. 사건마다 다음을 남긴다.
- 시각, 종류(`request` 요청 / `plan` 계획 / `added` 추가 / `modified` 수정 / `removed` 삭제 / `reverted` 되돌림 / `test_change` 테스트 후 변경 / `bug_fix` / `problem` / `deploy` / `data_ops`)
- 한 문장 요약, 이유, **원문 인용(근거)**, 관련 커밋 해시

## 4. 검증
1. 다른 사람(또는 다른 에이전트)이 사건마다 원문과 `git show --stat <해시>`를 대조해, 근거가 없는 사건은 지우고 과장된 요약은 고친다.
2. `git log --author=<이름>`의 커밋이 모두 어떤 사건에 연결됐는지 확인한다. 빠진 커밋이 있으면 그 시각 전후 기록을 다시 읽는다.

## 5. 문서로 옮기기
- **Todo 리스트**: 사용자 요청과 작업 목록(TaskCreate 등)을 날짜별 단계로 묶고, 완료 항목에 커밋 해시를 단다.
- **Todo 변경 내역**: `modified`/`test_change`/`removed`/`reverted`/새로 생긴 `added`를 "처음 계획 → 바뀐 결과 → 이유" 표로 정리한다.
- **느낀 점 재료**: `problem` 사건과 사용자의 원문 반응을 모아 둔다. 느낀 점 자체는 본인이 직접 다듬는다.

## 6. 공개 전 점검
비밀번호, API 키·토큰, 계좌번호, 이메일, 전화번호는 문서에 옮기지 않는다(`[가림]`으로 바꾼다).
